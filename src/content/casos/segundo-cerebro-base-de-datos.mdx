## Contexto

Heredé una base de datos cuyas consultas estaban muy desordenadas. Para entenderla tuve que estudiarlas una por una.

## Problema

Estudiar las consultas por separado no mostraba cómo se relacionan: qué proceso usa qué tabla y qué procedimiento depende de cuál.

## Solución

Diseñé un segundo cerebro: una nota por cada proceso, tabla y procedimiento almacenado, enlazadas entre sí.

El mapa parte de una nota de inicio y agrupa el contenido en mapas de procesos, de objetos, de conceptos, de casos y de herramientas. Cada proceso queda conectado con las tablas y los procedimientos que toca y con las capas por las que pasa el dato: landing, staging y fact. También reúne un glosario, las alertas y riesgos, y las preguntas abiertas.
